### `dexa.ts`, `mr-yoda.ts`, `cianahealth.ts` — structure real, specifics written

You gave me names and industries. The UX reasoning, the design arguments and

> Be careful here. A hiring manager will ask "how did you measure that" about

## 4. Testimonials — `src/data/testimonials.ts`

Deliberately **empty**. The section does not render at all while the array is
empty. Add real quotes and it appears automatically:

```ts
export const testimonials: Testimonial[] = [
  { quote: '…', name: '…', role: '…', organisation: '…' },
];
```

An invented testimonial is the fastest way to lose a reader's trust, so I left
it to you.

## 5. Contact delivery — `.env`

Copy `.env.example` to `.env` and set `PUBLIC_CONTACT_ENDPOINT`. Until you do,
the form validates and hands the message to the visitor's mail client — which
works, but a server endpoint is better for a portfolio (no mail client needed,
and you get a record).

Free options that take a JSON POST: Formspree, Web3Forms, Basin. For GitHub
Pages, add the value as a repository secret of the same name.

## 6. Project artwork — `public/media/*.svg`

Original abstract renderings of each product's core interaction, generated by
`scripts/build-covers.mjs`. They are honest — clearly stylised, not passing as
screenshots.

**If you have real screens**, replace them: drop images into `public/media/`
and point `cover.src` at them in the case-study file. Keep a 22:15 ratio, and
keep the `width`/`height` attributes so nothing shifts while loading. Then
regenerate the social cards with `npm run og`.

## 7. Photography

There is no photograph of you anywhere on the site. That is a deliberate gap,
not an oversight — a portrait helps recruiters, and only you can supply one.
Good places for it: the About aside (`src/components/About.astro`) and the
contact section.
